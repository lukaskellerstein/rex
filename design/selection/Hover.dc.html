HOW IT BEHAVES The mode is explicit — the hint at the foot of the page, P, or holding ⌥ for a moment. It left the top bar: it was the only mode in a row of facts about the document, and it belongs where it acts. Hover never outlines things while you are only reading, and it never competes with dragging a text selection. Hovering lands on the smallest anchorable element under the cursor. Inline runs — span, em, a — resolve up to their block, which is what nearestElement() already does. The path bar is the widening control: click a crumb, or ↑ / ↓. It is the same widening as the chips on a selection-panel row, moved before the click instead of after — both write the same Anchor. The panel rebuilds its chain from the row's stored anchor, so a row can still be widened after the document has been reloaded.
WHY SHOW STRENGTH AT ALL Because the reviewer can act on it. A bare <div> with no id and no text is a weak anchor — a positional path and nothing else, exactly the case create.ts warns lands on an unrelated element after an edit. Seeing that before clicking, they can widen one level to something with text. The three tiers read straight off what is being stored: stable id → durable; text quote → fair; path only → weak.
