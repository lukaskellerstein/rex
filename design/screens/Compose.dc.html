Widget service notes
The widget service accepts requests on a queue and writes results to the database. Each request is acknowledged before the work begins, so a crash between acknowledgement and commit is invisible to the caller.
Caching
Responses are cached for sixty seconds. The cache is keyed by the request id, which means two identical requests from different users share an entry — a correctness problem rather than a performance one.
Retries
A failed write is retried three times with no backoff, then dropped. The queue keeps no record of what was dropped, so the only signal available downstream is a gap in the results table.
Open questions
Whether the sixty second window is documented anywhere the caller can see it, and whether a schema change may ship in the same release as the code that reads it.
