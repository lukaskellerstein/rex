THE MEASURE APPLIES TO MARKDOWN ONLY 620px at 15 / 1.68 is REX's own typography, and it is the one document REX is entitled to set. Sanitised author HTML keeps its own styles and never sees this sheet; a <webview> URL is untouchable. For those two the pane supplies only the paper ground and the gutter — so the design has to survive a document looking like anything at all. Light only, deliberately. Following the system into dark mode would make a Markdown file look nothing like the HTML file beside it in the explorer, and would put a review's two halves on different grounds.
TWO RULES THAT LOOK LIKE DETAILS AND ARE NOT An alert's label is generated content. It is drawn with ::before, never as real text, so it never enters the anchor text index. Emit it as text and every comment below that callout moves. The stylesheet string may not contain an angle bracket. DOMPurify's mXSS guard deletes any element whose text matches /<[/\w!]/, and a style element holding CSS is exactly that shape. One bracket in a comment inside it deletes the whole sheet — the document renders completely unstyled and nothing logs a word. test/markdown.spec.ts asserts it.
FOUR FORMATS, THREE PATHS Markdown takes this sheet. HTML is sanitised and served as its own bytes. DOCX goes through mammoth in main and takes the Markdown path — the cheapest of the three to add, and the opposite of what the old tier table implied. It loses page layout, fonts, text boxes and tracked changes, which is acceptable because REX anchors on text: a comment's unit is a passage, not a page. PDF is the odd one. Chromium never composites a <canvas> inside a frame sandboxed without allow-scripts — which is exactly what the document iframe must be. The bitmap is really there and the page still shows as blank paper. So PDF.js draws into the renderer's own document and only the finished picture crosses in, as an <img> beside the page, never inside it: a region anchor fingerprints the element's markup, and a page that gained a bitmap when it happened to be painted would orphan every region on it. Which is also why a PDF's selection colour is translucent — rgb(47 93 168 / 30%), not the solid #b6d0f2 a Markdown page uses. The glyphs are in the bitmap behind the text layer; the spans over it hold the same words in transparent ink so they can be selected. An opaque fill paints over the picture and the selected sentence turns into an empty blue bar.
